# 文档类型骨架

各文档类型的信息流模板。遵循此处定义的**顺序**。每个 `→` 代表一个连续的内容块。

## feature

```
# <emoji> <功能名>
→ 1-2 句机制描述（程序做了什么，不说为什么）
→ GIF/截图用 HTML 表格：<table><tbody><tr><td><img src="..."></td></tr></tbody></table>
→ ## 使用 or ## 输入
  → 编号子章节（#### 1. 方式A / #### 2. 方式B）
    → 每个：有前置条件则加容器 + 一行描述 + 👉操作提示
→ ## 其他 or ## 功能相关
  → 限制/注意事项列表
→ 交叉引用链接：### [🔗适用的网站](/feat/#适用性)
```

关键模式：
- 先写机制描述（1-2句），紧接着放视觉演示
- 子功能用编号 #### 标题，不用散文
- 每种输入方式 = 独立子章节
- 末尾放关联页面交叉引用

## changelog

```
# 🕑 更新历史
→ ## `vX.Y.Z`（最新版本，完整展开）
  → ### 🎁 Features
    → + <emoji> 描述 [链接](url) by [@用户](url) in [#PR](url)
  → ### 🐞 Fix
    → + 描述
  → ::: tip 备用更新方法
→ > [!Info] 分隔注释
→ ::: details vX.Y.Z-1（旧版本，折叠）
  → + 条目
  :::
→ ::: details vX.Y.Z-2
  ...
→ <details><summary>古早记录</summary>（远古版本，嵌套 HTML+VitePress）
```

关键模式：
- 最新版本 = 完整展示，含子章节
- 旧版本 = `::: details vX.Y.Z` 折叠
- 远古版本 = HTML `<details>` 包裹多个 `::: details`
- 列表符始终用 `+`，功能 emoji：✨ 新增 / 🌐 站点 / 🐞 修复
- 贡献者署名：`by [@name](url) in [#PR](url)`

## faq

```
# ❓ <标题>
→ ## 1. 分类名
  → ::: warning（严重注意事项，如有）
  → ### 问题描述
    → 1-3 行直接解决方案
    → 需要 CLI 命令则加代码块
    → 关联文档链接
→ ## 2. 分类名
  → ...
→ --- 分隔线
→ ::: warning 兜底引导（提交 issue / 加群）
→ <iframe>（Discord 小部件等）
```

关键模式：
- 顶层分类用编号（`## 1.`、`## 2.`）
- 问题作为 `###` 子标题，解决方案紧跟其后（无"答："前缀）
- 直接简洁——不用问答体散文
- 末尾放"如果你的问题不在列表中"兜底

## config

```
# 🔨 <标题>
→ 配置界面截图
→ ::: info 配置文件路径说明
→ ::: warning 格式注意（yaml 缩进等）
→ ## 章节标题 / 对应 `yml` 字段
  → ### 字段名 / `yml_key`
    → 一行机制描述
    → 默认值：`win: X` `macOS: Y`
    → ::: warning 或 ::: tip（如有注意事项）
  → ---
  → ### 下一个字段 / `yml_key`
    → ...
→ ## 其他 `yml` 字段
  → ::: info（无 GUI 编辑器的字段）
  → ### `field_name`
    → 默认值 + 一行描述
```

关键模式：
- 每个配置字段 = 独立 `###` 章节，带 `/yml_key` 后缀
- 一行描述（机制，不是好处）
- 默认值带平台标签
- `---` 分隔线分开逻辑字段组
- 无 GUI 的字段放"其他"章节

## deploy

```
# 🚀 <标题>
→ ::: warning 关键前置条件
→ ## 1. 步骤名
  → + 主要指令 + 链接
  → ::: warning 平台特定注意事项
  → ::: danger + ::: details（错误处理，折叠）
  → + 备选方法
  → ::: details（详细子步骤，折叠）
  → ::: tip（轻量替代方案）
→ ## 2. 步骤名
  → ::: tip 前置说明
  → ### 子方法 A
    → 代码块（cmd/bash/zsh 带语言标签）
  → ### 子方法 B
    → ...
→ ## N. 最终步骤
  → 推荐 + 徽章/卡片链接
```

关键模式：
- 主要步骤用编号（`## 1.`、`## 2.`）
- 大量使用 `::: details` 处理可选/错误处理内容
- 平台特定代码块带正确语言标签（cmd/bash/zsh）
- 允许容器嵌套（danger 嵌套在 details 内）

## dev

```
# ✒️ <标题>
→ 一行状态/计划说明
→ ## 主题
  → #### 准备
    → 所需材料列表
  → #### 实施
    → 编号步骤 + 代码位置
    → ::: details（prompt 模板或长代码，折叠）
    → > [PR 引用链接]
→ ## 注意事项
  → 流程/可靠性警告
  → ::: details（旧版指南，折叠）
```

关键模式：
- 指令密集，代码为中心
- 用 `::: details` 折叠长 prompt 模板
- 引用具体文件/类，附 GitHub 链接
- ✅ 必须 / 🔳 可选 标记类属性/方法
- `> [!tip]` 或 `> [!TIP]` blockquote 告警与 `::: tip` 混用

## unknown（新/未知文档类型的回退骨架）

使用此骨架前，先判断文档的**意图**：

| 意图 | 最近的已知类型 | 适配来源 |
|---|---|---|
| 如何使用某功能 | feature | feature 骨架 |
| 排错/问答 | faq | faq 骨架 |
| 版本发布说明 | changelog | changelog 骨架 |
| 安装/部署 | deploy | deploy 骨架 |
| 参考/设置 | config | config 骨架 |
| 贡献者指南 | dev | dev 骨架 |
| 以上都不是 | — | 使用下方通用骨架 |

```
# <emoji> <标题>
→ 1-2 句机制描述（做了什么）
→ 可视化元素（截图/GIF 占位，如适用）
→ ## 使用 or ## 用法
  → 编号步骤或功能表格
  → 👉用户交互操作提示
→ ## 注意 or ## 其他
  → ::: tip / ::: warning 用于注意事项
  → 限制条件列表
→ 关联页面交叉引用（如有）
```

unknown 类型防护栏：
- 严格遵循声音合约——未知类型不等于未知声音
- 禁止发明已知骨架中不存在的结构模式
- 拿不准时，优先最简结构（纯文本 > 容器 > 复杂布局）
